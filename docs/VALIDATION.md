## USB ADB 的独立重启验证

先确认单次写入 `adb_enabled=1` 会在重启后被系统改回 0。随后安装带独立 USB 保持逻辑的助手 v3，启用后进行真实重启。

重启后 USB transport 自动上线，shell 身份为 `uid=2000`，`development_settings_enabled=1`、`adb_enabled=1`、`adb_wifi_enabled=1`。此次开机没有手工补写 USB 值。之后约 20.9 秒的连续检查保持在线。

无线调试长期授权已建立，端口仍随系统变动；没有声称固定端口、所有路由器 mDNS 可用或完全不需要用户首次确认。

## 为公开发布重新执行的主机检查

- 从固定 SHA-256 的原版重新解包、打补丁、重建影院，11 个 DEX/原生库内容哈希全部匹配实机 v7；apksigner 校验通过。
- 从发布的完整 Java/资源构建助手 v3，必要类检查、Manifest 和资源匹配检查、签名验证通过。重建后的 DEX 不承诺字节级一致。
- 10 项 Python 测试：补丁上下文和 hunk 数量、缓存哈希拒绝、补丁清单、错误设备拒绝、同机双连接优先 USB、多头显需指定、写前重查身份、连接扫描范围、Sunshine 配置保护。
- 两组 Java 测试覆盖按压滞回、混合输入、松开/暂停复位，以及单击、双击、三击、拖动、长按和不同目标。
- RTP 原版崩溃被复现；修复源码通过 ASan/UBSan 的正常、重复、回绕、超时、容量路径。
- 发布前对源码与 Release 助手 APK 检查个人标识和凭据，不包含原始会话日志与运行配置。

这些主机检查没有把重新签名的测试 APK 安装到已配置好的用户设备，也没有重新改变其工作状态。通用 `tools/quest.py` 和配置生成器是发布时新增的便携封装，做了模拟/本地测试；底层命令已有实机记录，但新封装没有重新做整套设备端安装测试。
