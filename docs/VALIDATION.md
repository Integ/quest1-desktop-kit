## USB ADB 的独立重启验证

先确认单次写入 `adb_enabled=1` 会在重启后被系统改回 0。随后安装带独立 USB 保持逻辑的助手 v3，启用后进行真实重启。

重启后 USB transport 自动上线，shell 身份为 `uid=2000`，`development_settings_enabled=1`、`adb_enabled=1`、`adb_wifi_enabled=1`。此次开机没有手工补写 USB 值。之后约 20.9 秒的连续检查保持在线。

无线调试长期授权已建立，端口仍随系统变动；没有声称固定端口、所有路由器 mDNS 可用或完全不需要用户首次确认。

## 为公开发布重新执行的主机检查

- 公开流程成功编译 v8 原生网络模块，并完成两阶段 APK 构建：先验证 v7 的全部 11 项 DEX/原生库哈希，再保留已验证 DEX，改变 API/版本元数据并插入网络库。最终其余 10 项代码/库与基线一致，网络库与指定输入哈希一致。
- `aapt` 确认最终 APK 为 versionCode 8、versionName `1.0-quest-left-stereo-multifec`、最低 API 29；`apksigner verify` 通过。提升最低 API 时没有重新编译 smali 改变既有 DEX。
- 从发布的完整 Java/资源构建助手 v4，必要类与签名验证通过。重建后的 DEX 不承诺字节级一致。v0.2.0 沿用未改动的助手源码及原先实机验证的 v4 Release APK；原签名、偏好和权限不变。
- 20 项 Python 测试全部通过，覆盖补丁、缓存、设备选择和 Sunshine 配置保护、音量快捷键开关、固定原生源码暂存与未知修改拒绝、NDK 版本限制，以及 v8 的最低 API 元数据和 Java 代码保护。
- 三组 Java 测试全部通过：左手输入状态、双击手势、音量序列。音量检查覆盖完整序列、超时、冷却、普通长按、静音不变和无效数据。
- RTP 原版崩溃被复现；修复源码通过 ASan/UBSan 的正常、重复、回绕、超时、容量路径。
- 新的原生视频回归用生产 `RtpFecQueue.c` 和真实 Reed–Solomon 纠错，覆盖三块重组、乱序、重复、丢块、注入重建失败、RTP/帧号回绕和畸形输入。提取的生产 RTSP、控制与载荷处理函数覆盖 Session 长度/空白/timeout、显式 IDR、旧协议回退、跨块边界、纠错索引间隙、损坏拒绝与下一帧恢复，ASan/UBSan 检查全部通过。测试桩隔离了网络和解码器，并非完整头显集成测试。
- 发布前对源码与 Release 助手 APK 检查个人标识和凭据，不包含原始会话日志与运行配置。

公开脚本重新构建的验证 APK 没有覆盖用户设备；实际修复版 v8 已沿用设备原签名安装并完成下述测试。通用 `tools/quest.py` 和配置生成器是发布时新增的便携封装，做了模拟/本地测试；底层命令已有实机记录，但新封装没有重新做整套设备端安装测试。

## 历史记录：助手 v4 与影院 v7

影院 v7 后续发生一次 `RtpFecQueue.c:147` / `reconstructFrame()` / `ret == 0` 断言退出。它属于视频纠错，与之前修复的音频 RTP 乱序断言不同；当时助手 v4 只提供退出后的入口，没有改变影院代码。后续 v8 的修复与验证记录如下。

系统 `SettingsManager` 的 `swap_system_button_handedness` 读取为 false，setter 返回 false，设置未改变。打开原生设置页时仍进入未完成的首次初始化流程，用户确认未看到设置页面，因此没有把系统按钮交换记为成功。

随后安装同签名助手 v4 并启用音量快捷入口。日志记录媒体音量连续四次变化后打开启动器；用户确认用头显实体音量键可以打开应用列表。安装后版本为 v4，原有 USB / Wi-Fi 调试仍开启，系统设置权限仍已授予。新版本没有增加权限，也没有改变已有开关。该轮未另外重启，所以不会把 v3 的重启结果算作 v4 的新重启验证。

## v8 视频修复的实机记录

早期修复尝试在连接时黑屏或退出，继续定位后修正了 RTSP Session 缓冲区与解析。最终 v8 以 HEVC 硬件编码、正常 FEC 和 Sunshine `max_bitrate = 8000` Kbps 建立桌面；用户移动窗口或播放视频约 3 分钟后确认“画面持续稳定，声音正常”。

这段运行记录持续 181 秒，未出现新的 fatal signal 或 FATAL EXCEPTION。期间有真实帧丢失，客户端发出显式 IDR 请求后恢复视频；结束经过正常 `nativePause` / `StopMovie` 生命周期。原有配对、左手控制与立体声功能保留。已测构建指纹和去标识说明保存在 `cinema/native/tested-build.json`，原始运行日志不公开。

Mac VideoToolbox 仍有部分关键帧警告；短时恢复成功不表示所有编码器警告都已消除。8 Mbps 限制是本次验证条件，不能独自修复旧客户端协议和帧重组错误。没有为影院 v8 或助手 v4 新做重启测试，也没有把约 3 分钟测试扩展为长期稳定性保证。
